## 📌 Статус модулей

### ✅ Реализовано и работает
1. **Каталог и витрина**
   - Поиск по названию/артикулу, пагинация (24 на страницу). Показываются товары с рассчитанной `our_base`, не скрытые в админке (`products.is_active = 0`).
   - Карточка `/catalog/{sku}`: цены, характеристики (`moba_prices.specifications` — JSON), остатки по городам. Несуществующий артикул → страница 404.
   - Тёмная/светлая тема (`localStorage`).

2. **Корзина и заказы**
   - Гостевая корзина в Redis (`cart:{cart_id}`, TTL 30 дней), у авторизованного — `user_cart`; изменения в БД сразу коммитятся.
   - При входе гостевая корзина переносится в аккаунт (количество из гостевой заменяет сохранённое).
   - Счётчик в шапке — сумма штук (одинаково для Redis и БД).
   - Оформление `/checkout`: город берётся из таблицы `cities`, цена — с сервера (опт для роли `WHOLESALE`).
   - Заказ создаётся в одной транзакции вместе с очисткой корзины: остатки блокируются `SELECT … FOR UPDATE`, пишутся `profit` (по `purchase_price`) и движения `SALE`. При нехватке — возврат в корзину с текстом ошибки.
   - История заказов с составом в личном кабинете.

3. **Авторизация**
   - Регистрация (логин 3–50 символов, уникален без учёта регистра; пароль 8–128), вход, выход.
   - `hashlib.pbkdf2_hmac(sha256)`, 260 000 итераций, `hmac.compare_digest`.
   - Заявка на оптовые цены из личного кабинета.

4. **Админ-панель `/admin`** (повторяет админку Telegram-бота PartsBot, доступ по ролям — см. README)
   - **Дашборд:** сводка склада (позиции, штуки, оценка в рознице и по себестоимости, ожидаемая прибыль, низкие остатки, новые заказы и заявки) и KPI продаж за сегодня / 7 / 30 дней / всё время, топ клиентов и товаров.
   - **Заказы:** фильтр по статусу, пагинация, карточка заказа с составом, смена статуса. Отмена возвращает товар на склад города заказа (`RETURN`), восстановление отменённого заказа снова списывает.
   - **Продажи и ABC:** KPI, распределение по статусам, ABC-анализ (A — 80% выручки, B — 15%, C — остаток и товары без продаж), кандидаты на акции, топ клиентов.
   - **Финансы:** выручка и прибыль по выполненным заказам, оценка склада, средняя наценка, топ-10 по марже.
   - **Товары:** поиск, фильтры (в каталоге / низкий остаток / скрытые), создание товара (создаётся и запись `moba_prices`, и нулевые остатки по городам), редактирование цен/себестоимости/порога/поставщика, ручная корректировка остатков по городам (`ADJUSTMENT`), скрытие из каталога, история движения.
   - **Склад:** приход (поставщик, закупочная цена, примечание), списание (`WRITE_OFF`), журнал движения с фильтром по типу и сводкой прихода/расхода за 7/30/90 дней, низкие остатки, прогноз закупок (темп расхода за 30 дней, запас в днях, рекомендуемый дозаказ).
   - **Поставщики:** список, добавление, аналитика поставок (число приходов, штук, средняя партия, сумма закупок, последняя поставка).
   - **Пользователи:** поиск, пагинация, смена роли (нельзя снять ADMIN с самого себя).
   - **Заявки на опт:** одобрение/отклонение; одобрение переводит покупателя в `WHOLESALE`.
   - **Настройки цен:** `COEF_BASE`, `COEF_CARD`, `COEF_OPT`, `BASE_FROM` с валидацией и опциональным пересчётом цен. Пересчёт касается только товаров, загруженных парсером Мобы (`moba_prices.url` заполнен); цены поставок и товаров из админки не меняются.
   - **Экспорт CSV:** заказы, остатки, движение за 60 дней, комплексная аналитика (KPI, клиенты, ABC, прогноз). Разделитель `;`, UTF-8 с BOM.
   - **Рассылки:** только черновики — у аккаунтов нет e-mail, SMTP не настроен.

## 💬 Чат с менеджером

- **Покупатель:** кнопка «Чат с менеджером» на всех страницах витрины (`_chat_widget.html`). Писать можно без регистрации — диалог хранится по `chat_token` в сессии; гость может оставить имя и телефон. При входе/регистрации диалог привязывается к аккаунту (если у аккаунта уже есть диалог — переписка объединяется). На странице товара: «Спросить менеджера о товаре», у товаров без цены — «Узнать цену в чате».
- **Администратор:** админка → «Обращения». Список открытых / моих / закрытых, счётчик обращений без ответа в меню. В диалоге — карточка покупателя (контакты, страница, с которой писал, корзина и последние заказы для зарегистрированных), быстрые ответы, поиск товара с отправкой ссылки, «Взять себе», «Закрыть обращение». Кто ответил первым — тот и ведёт обращение. Новое сообщение покупателя переоткрывает закрытое обращение.
- **Как устроено:** таблицы `chat_threads`, `chat_messages` (миграция `d4e8a2b6c1f0`), сервис `app/services/chat.py`, API `/chat/state`, `/chat/send`, `/admin/api/chats/...`. Обновление — опросом: окно чата раз в 3 с, свёрнутый виджет раз в 20 с, админка раз в 3 с. Текст сообщений выводится только как текст (`textContent`), ограничения: 2000 символов, не больше 10 сообщений за 30 с с одного диалога.
- **Защита от флуда:** не больше 10 сообщений за 30 с в одном диалоге и 60 за 10 минут с одного IP.
- **Ограничения:** счётчик защиты от флуда хранится в памяти процесса; уведомлений менеджеру вне админки (Telegram, звук) пока нет.

## 🤖 Сайт и Telegram-бот — один бэкенд

- Бот (`app/bot`, `python -m app.bot`) работает с той же базой и сервисами, что сайт: цены — `pricing.buyer_prices`, корзина — `services.cart.user_*`, заказ — `order_service.create_order(source="bot")`, переписка — `ChatThread`. Отдельной базы и синхронизации нет: изменения сайта сразу действуют в боте.
- Покупатель из бота получает аккаунт автоматически (`username = tg<id>`, без пароля). Привязка Telegram к существующему аккаунту (кабинет → «Привязать Telegram») переносит заказы, корзину, переписку и заявки (`accounts.link_telegram`).
- Одноразовые токены в Redis (`tg:link|login|reset:<токен>`, 10/10/30 мин): привязка, вход без пароля (сайт опрашивает `/auth/telegram/poll`), сброс пароля (ссылка уходит в Telegram).
- Mini App: `/tg/app` → `POST /tg/auth` проверяет подпись initData и входит; дальше обычный сайт. CSP разрешает встраивание только Telegram Web.
- Уведомления (`services/telegram.py`) отправляются фоном и не ломают запрос. Администраторы — пользователи с ролью ADMIN и привязанным Telegram. Кнопки в уведомлениях: `ord:<id>:<STATUS>`, `ws:<id>:<решение>`, `chat:<id>:reply`.
- Админка опрашивает `/admin/api/events` раз в 5 с: счётчики в меню и во вкладке, всплывающие уведомления со звуком, список обращений обновляется фрагментом (`/admin/chats?partial=1`).
- Админ-функции старого бота (аналитика, склад, рассылки) — в админ-панели сайта; в боте у администратора уведомления, быстрые действия и сводка `/admin`.
- Старый репозиторий бота (vexillumisreal/PartsBot, SQLite) больше не развивается. Покупателей из его базы (Telegram id, имя, оптовый статус) переносит `python -m scripts.import_bot_users spare_parts.db` — скачайте файл базы с хостинга бота и запустите один раз; каталог и заказы старого бота не переносятся.

## 💰 Ценообразование

Коэффициенты хранятся в `system_config` и редактируются в «Настройках цен»:
- **`our_base`** = цена поставщика × `COEF_BASE` (0.9). Источник — обычная или дисконтная цена (`BASE_FROM`).
- **`our_card`** = `our_base` × `COEF_CARD` (1.1).
- **`our_opt`** = `our_base` × `COEF_OPT` (0.9).

Пересчёт: чекбокс в «Настройках цен» или `python -m app.services.pricing` — только для товаров парсера Мобы.

**Цена для покупателя** — одно правило везде (витрина, подсказки, корзина, заказ): `pricing.buyer_prices()`.
- Розница: наличными/переводом `our_base`, картой при получении `our_card`.
- Опт (роль `WHOLESALE`): `our_opt`, если задана, иначе розница; картой — опт с той же наценкой за карту (`our_opt × our_card / our_base`).
- Нет `our_base` — «Цена по запросу», в корзину и заказ товар не попадает.
- Суммы выводятся с копейками, только если они есть: «2 875,50 ₽», «208 ₽» (макрос `money` в `_ui.html`).

Те же правила в Telegram-боте и Mini App (`pricing.py` бота) — изменения сайта повторяются в боте.

В `system_config` остались неиспользуемые ключи `price_*_multiplier` от прежней версии формы настроек — их можно удалить.

## 🛠 Технические особенности

1. **Порядок middleware.** Starlette выполняет middleware в обратном порядке добавления, поэтому `SessionMiddleware` добавляется последней — тогда `add_user_to_request` видит `request.session` и кладёт пользователя в `request.state.user`.

2. **Windows и psycopg async.** uvicorn без `--reload` на Windows использует `ProactorEventLoop`, с которым psycopg async не работает. `lifespan` в `app/main.py` останавливает приложение с понятной ошибкой; запуск — с `--loop asyncio:SelectorEventLoop` или `--reload`.

3. **Транзакции.** `get_db()` не коммитит сам. Сервисы корзины коммитят изменения; `order_service.create_order` только готовит заказ, а коммит делает роутер — чтобы очистка корзины попала в ту же транзакцию. Нельзя вызывать `db.begin()` после запросов в той же сессии: SQLAlchemy уже открыл транзакцию (autobegin).

4. **Остатки.** Остаток — `stocks` по городам. Любое изменение пишется в `inventory_transactions` знаковой дельтой (`quantity > 0` — приход, `< 0` — расход) с типом `RECEIPT / WRITE_OFF / SALE / RETURN / ADJUSTMENT / TRANSFER`.

5. **Две таблицы товаров.** Витрина читает `moba_prices` (цены, название), склад и заказы — `products` (+ `stocks`). Связь по `sku`. Создание и редактирование товара в админке обновляет обе.

6. **Агрегаты с `GROUP BY`.** Не используйте `joinedload` в агрегирующих запросах (PostgreSQL `GroupingError`) — только `selectinload` или подзапросы, как в `app/services/analytics.py`.

7. **CSP.** Разрешены `cdn.tailwindcss.com`, `unpkg.com` (HTMX), `cdn.jsdelivr.net`, Google Fonts. Новый CDN нужно добавить в `add_security_headers`, иначе браузер заблокирует скрипт.
