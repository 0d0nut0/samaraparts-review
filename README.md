## 🚀 Возможности

| Модуль | Описание |
| :--- | :--- |
| **Каталог** | 6 разделов (запчасти для телефонов; аксессуары; ПК, ноутбуки, ТВ и консоли; защита и память; оборудование и инструменты; элементы питания) с группами и подгруппами, карточка товара с остатками по городам. Скрытые в админке товары не показываются. |
| **Поиск** | По ключевым словам с синонимами и подсказками в выпадающем списке: «iPhone 11 дисплей», «realme c67 акб», «honor 10i дисплей в рамке», артикул. Те же подсказки — в приходе и списании в админке. |
| **Чат с менеджером** | Покупатель пишет с сайта (можно без регистрации) или в боте — это одна переписка. Менеджер отвечает в админке → «Обращения» (список обновляется без перезагрузки) или прямо в Telegram кнопкой «Ответить»; из обращения можно сразу оформить заказ за покупателя. |
| **Telegram-бот** | `python -m app.bot` — та же база: каталог и поиск, карточка товара, корзина, оформление, мои заказы, заявка на опт, переписка с менеджером. Администратору — уведомления о заказах, обращениях и заявках с кнопками действий. Mini App (кнопка «Магазин») открывает сам сайт и входит по подписи Telegram. |
| **Вход** | Регистрация с e-mail и одноразовым подтверждением (24 часа), повтор и проверка сложности пароля; логин и пароль, вход через Telegram без пароля, восстановление пароля ссылкой в привязанный Telegram, привязка/отвязка Telegram и смена пароля в кабинете. |
| **Уведомления** | Новый заказ (сайт, бот, менеджер) — администраторам в Telegram; подтверждение и смена статуса — покупателю, если Telegram привязан. В админке — всплывающие уведомления, звук и счётчики без перезагрузки. |
| **SEO** | `robots.txt`, `sitemap.xml` (все товары и разделы), canonical, description, Open Graph, разметка schema.org (Product/Offer, BreadcrumbList, Store); поиск, корзина и кабинет закрыты от индексации. |
| **Персональные данные** | Политика `/privacy` (текст — `app/legal.py`, файл для согласования — `docs/privacy_policy.docx`), согласие в регистрации и оформлении, шрифты раздаются с сайта (без Google Fonts). |
| **Страницы** | О компании, контакты и реквизиты, доставка, оплата, гарантия и возврат. Данные продавца — `app/shop_info.py`. |
| **1С** | Приём CommerceML (`/1c_exchange`) и выдача рассчитанных цен (`/1c/prices`). Состояние настройки облачной базы — [docs/1C_INTEGRATION.md](docs/1C_INTEGRATION.md). |
| **Цены** | Розница = Moba × 1,20; ОПТ = обычная Moba; СуперОПТ = max(ОПТ × 0,90, закупка × 1,15). Продажа в целых рублях, нижняя граница округляется вверх. Тариф назначает администратор. |
| **Корзина** | Гость — Redis (TTL 30 дней), после входа — таблица `user_cart`; при входе гостевая корзина переносится в аккаунт. |
| **Заказы** | Выбор города (склада), списание остатков в одной транзакции с `SELECT … FOR UPDATE`, фиксация прибыли и движения `SALE`. История заказов в личном кабинете. |
| **Оптовые цены** | Заявка из личного кабинета → модерация в админке → роль «Оптовый покупатель». |
| **Админ-панель** | Дашборд, заказы (в т. ч. оформление за покупателя, заметки менеджера), продажи и ABC-анализ, финансы, товары, приход по одной позиции и **поставкой из xlsx/csv**, списание, движение товара, низкие остатки (по товарам, которые держим на складе), прогноз закупок, поставщики, пользователи, настройки цен, экспорт CSV. |

## 🛠 Стек

- **Backend:** FastAPI, Python 3.11+ (проверено на 3.14)
- **БД:** PostgreSQL 16 (SQLAlchemy 2.0 async + psycopg 3), миграции Alembic
- **Кэш и гостевые корзины:** Redis 7
- **Frontend:** Jinja2, HTMX, Tailwind CSS (раздаются с сайта, `app/static`)
- **Telegram:** aiogram 3 (бот и уведомления)
- **Парсер цен:** HTTP-снимок публичного каталога moba.ru, проверка полноты перед записью

## 🏁 Развёртывание

### Хостинг ботов (bothost.ru) — всё в одном контейнере
Репозиторий подключается к боту в панели (собственный Dockerfile). Если `DATABASE_URL` не задан, контейнер сам поднимает
PostgreSQL и Redis с данными в `/app/data` (сохраняется между пересборками), при первом запуске загружает каталог
из `deploy/seed/catalog.sql.gz`, назначает администраторами Telegram из `ADMIN_ID`, переносит покупателей старого бота
(`/app/data/spare_parts.db`) и запускает сайт (порт `PORT`) и бота. Переменные в панели: `BOT_TOKEN` (вкладка «Токен»),
`PORT=8888`, `DATA_DIR=/app/data`, `ADMIN_ID`, `SITE_URL=https://<домен бота>`, `TELEGRAM_BOT_USERNAME`.
`SECRET_KEY` создаётся сам и хранится в `/app/data/secret_key`. Каталог для новой установки обновляется командой
из `deploy/entrypoint.sh` (pg_dump без данных покупателей).

### Сервер (Docker)
```bash
cp .env.example .env   # SECRET_KEY, SITE_URL=https://домен, TELEGRAM_BOT_TOKEN/USERNAME, DOMAIN, POSTGRES_PASSWORD
docker compose --profile prod up -d --build
```
Поднимаются: сайт (миграции применяются при старте), Telegram-бот, PostgreSQL и Redis (наружу не открыты),
Caddy с автоматическим HTTPS для `DOMAIN` и ночная копия базы в `./backups` (14 дней).
Первый администратор: `docker compose exec web python make_admin.py <логин>`, затем «Привязать Telegram» в кабинете —
уведомления начнут приходить.

### Разработка

### 1. PostgreSQL и Redis
```bash
docker compose up -d postgres redis
```

### 2. Окружение
```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/Mac
source .venv/bin/activate

pip install -r requirements.txt
```

Файл `.env` (шаблон — `.env.example`):
```env
DATABASE_URL=postgresql://partsbot:partsbot_secret@localhost:5432/partsbot
REDIS_URL=redis://localhost:6379/0
SECRET_KEY=<длинная случайная строка>
# HTTPS_ONLY=true   # на продакшене за HTTPS: secure-cookie и HSTS
```

### 3. Миграции
```bash
alembic upgrade head
```

### 4. Запуск
```bash
uvicorn app.main:app --reload
```
Сайт: `http://localhost:8000`. Бот (нужен `TELEGRAM_BOT_TOKEN` в `.env`): `python -m app.bot`.
Mini App работает только по https (`SITE_URL`), локально кнопка «Магазин» отключается.

> **Windows без `--reload`:** uvicorn по умолчанию берёт `ProactorEventLoop`, а async-драйвер psycopg на нём не работает.
> Запускайте `uvicorn app.main:app --loop asyncio:SelectorEventLoop` — иначе приложение остановится при старте с подсказкой.

## 🔐 Роли и доступ

Три роли:

| Роль | Кто это | Доступ |
|---|---|---|
| `ADMIN` — Администратор | сотрудник магазина | вся админка: обращения, заказы, товары и склад, аналитика, пользователи, настройки |
| `WHOLESALE` — Оптовый покупатель | клиент с одобренной заявкой на опт | витрина по оптовым ценам |
| `RETAIL` — Покупатель | любой зарегистрированный клиент | витрина по розничным ценам |

Админку проверяет зависимость `require()` в `app/routers/admin.py`: пускает только администратора.
Флаг `users.is_admin` равнозначен роли `ADMIN`. Роли сотрудников `MANAGER` и `WAREHOUSE` удалены
миграцией `e9a1c7d3f5b2` (такие пользователи стали розничными покупателями).

Первого администратора назначьте из консоли (пользователь должен быть зарегистрирован на сайте):
```bash
python make_admin.py <имя_пользователя>
```
Дальше роли меняются в админке, раздел **«Пользователи»**.

## 🛡 Безопасность

- Заголовки: CSP (только свои скрипты и шрифты + telegram.org для Mini App; встраивание во фрейм — только Telegram Web), `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store` на личных страницах; HSTS — при `HTTPS_ONLY=true`. Автодокументация API (`/docs`, `/openapi.json`) выключена.
- Сессии: подписанная cookie (`SECRET_KEY`), новая сессия при входе (защита от session fixation), `SameSite=Lax`; в сессии — отпечаток пароля, после смены пароля остальные сессии разлогиниваются.
- Пароли: PBKDF2-SHA256, 260 000 итераций, сравнение за постоянное время.
- Вход: не больше 10 неудачных попыток за 15 минут на логин и на IP; запросов сброса пароля — 3 за 15 минут. IP клиента берётся из `X-Forwarded-For` только от прокси в частных сетях (`FORWARDED_ALLOW_IPS`).
- Telegram: вход и привязка через бота — только после подтверждения кнопкой (бот показывает IP и браузер запроса), иначе присланной ссылкой можно было бы войти в чужой аккаунт. Ссылки входа/привязки/сброса одноразовые и с ограниченным сроком. Подпись Mini App (initData) проверяется и действует 1 час. Действия администратора в боте проверяют права на каждой кнопке.
- Цены в заказе берутся с сервера, а не из формы; товар без цены («Цена по запросу») или скрытый в корзину и в заказ не попадает.
- Экспорт CSV экранирует значения, которые Excel принял бы за формулу (`=`, `+`, `-`, `@`).

## Обновление регистрации, цен и оформления

После обновления кода выполните `alembic upgrade head` (в Docker миграции применяются при старте).
Миграция добавляет email и поля подтверждения без изменения существующих аккаунтов и заказов.
Существующие аккаунты без email и Telegram-вход продолжают работать; новый аккаунт с email
не получает сессию до подтверждения адреса. При открытии ссылки показывается кнопка подтверждения,
GET не расходует токен. После подтверждения пользователь входит своим паролем; гостевая корзина сохраняется.
Повторная отправка: `/auth/resend-verification`, максимум 3 запроса за 15 минут на адрес/IP.
Токены хранятся в виде SHA-256, действуют 24 часа, повторная отправка заменяет предыдущую ссылку.

Укажите `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` и публичный
`SITE_URL` в окружении. Порт 587: `SMTP_STARTTLS=true`, `SMTP_SSL=false`;
порт 465: `SMTP_SSL=true`, `SMTP_STARTTLS=false`. Пароли хранятся только в окружении.
В режиме `REGISTRATION_EMAIL_ENABLED=true` без настроенной почты регистрация не создаёт аккаунт.
При ошибке SMTP после создания аккаунт остаётся неподтверждённым, письмо можно запросить повторно.
Проверка реальной доставки требует настроенного SMTP. Маркетинговые рассылки не включаются.

Новые пароли: 8–128 символов, заглавная и строчная буквы, цифра и специальный символ;
проверка совпадения и состава выполняется в браузере и на сервере при регистрации, смене и сбросе.
Существующие пароли при входе не изменяются.

Для запуска без почтового отправителя: `REGISTRATION_EMAIL_ENABLED=false`.
Новые покупатели регистрируются по логину и паролю и сразу входят; e-mail при этом
не собирается. Старые аккаунты с неподтверждённой почтой не подтверждаются автоматически.
Восстановление: «Забыли пароль?» → помощь менеджера. Администратор после проверки
владельца открывает «Пользователи → Помочь со входом» и выдаёт ссылку на 30 минут.
Она одноразовая, клиент сам задаёт пароль; смена пароля отзывает остальные ссылки и сеансы.
Привязанный Telegram также поддерживает восстановление, если бот включён.
После настройки SMTP включите `REGISTRATION_EMAIL_ENABLED=true` и перезапустите сайт.

Печатные формы: «Админка → Заказы → заказ → Печать счёта / Печать накладной».
Кнопка «Печать / сохранить PDF» открывает системную печать, формат А4, масштаб 100%.
Печать берёт сохранённые цены заказа и не создаёт отдельную продажу или списание в 1С.

Правила цен от 04.11.2026: розница = ОПТ × 1,20; ОПТ = обычная розничная Moba;
СуперОПТ = максимум из ОПТ × 0,90 и закупки × 1,15. Нижняя граница округляется вверх.
Без закупки суперопт не рассчитывается; такому аккаунту доступна цена ОПТ.
Доставка и самовывоз не меняют тариф и не добавляют скидку. Новая схема заменяет прежнюю.
Цены заказа пересчитываются сервером; после оформления сохраняются в строках заказа.

Парсер: `python run_parser.py` проверяет данные без записи; `--apply` применяет полный снимок
и сохраняет резервную копию. Для готового снимка — `--snapshot var/prices/latest.json`.
На Mac автозапуск устанавливается `python -m scripts.install_macos_services --install`.
Для уже подготовленного туннеля: `python -m scripts.install_cloudflare_service --install`.
Docker с PostgreSQL и Redis должен работать; Mac должен быть включён и подключён к сети.
Крышку ноутбука держать открытой: `caffeinate -i` предотвращает сон по бездействию,
но не сон при закрытии крышки. Во сне сайт недоступен даже при работающем Cloudflare.
Туннель использует отдельные DNS-серверы для поиска серверов Cloudflare; состояние:
`http://127.0.0.1:20241/ready` (200 при активном подключении, адрес только локальный).

Зелёная тема ПАРТС распространяется на витрину, формы, личный кабинет, чат и админку;
светлая и тёмная темы адаптированы для телефона. Базовая палитра — в `base.html`,
оформление бренда — `app/static/brand.css`.
Самарский городской телефон сохранён как `8997040204` по указанию владельца.
Отдельные телефоны: `SAMARA_PHONE` и `KAZAN_PHONE`; статус Казани «Скоро открытие» — в `app/shop_info.py`.


### Проверка изменений

`pip install -r requirements-dev.txt` и `python -m unittest discover -s tests -v`.
Интеграционный сценарий дополнительно запускается с `PARTS_TEST_DATABASE_URL`
(отдельная PostgreSQL-база с именем, заканчивающимся на `_test`, предварительно примените миграции)
и `PARTS_TEST_REDIS_URL` (пустая отдельная Redis DB, не DB 0).
Тест очищает только явно указанную тестовую базу; не указывайте в этих переменных рабочие данные.
SMTP и Telegram подменяются в тесте: реальные письма и уведомления не отправляются.
